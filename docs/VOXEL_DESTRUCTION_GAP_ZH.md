# Avian / CCC 与体素破坏参考技术的差距

> 快照：2026-10-17；目标仓库：[`S1nF0x/avian`](https://github.com/S1nF0x/avian)；目标分支：`main`；基线提交：`c7fb5dd`。

本文记录当前 CCC（BREAKLINE）与 Avian 物理层对体素破坏目标的实现边界。它是工程排程与验收依据，不把架构设想当成已经验证的能力。

## CCC / Avian 当前状态

- CCC 的当前架构以稀疏 `8³` brick 作为体素权威数据，并用 dirty brick、局部连通性/支撑分析和派生碰撞体、网格、渲染缓存来降低更新范围。
- CCC 的结构完整性目前是材料承载力、载荷路径和连通性结合的近似模型；大规模结构、复杂偏心载荷和跨实体支撑仍需要运行时证据。
- Avian 已经提供子步求解、接触流形匹配、约束图着色、岛管理和 warm-start。
- `S1nF0x/avian@c7fb5dd` 已加入真实接触法向冲量上限，并将 restitution 与 warm-start 摩擦纳入同一容量约束；普通无限容量接触保持原有行为。
- 当前 Avian 的窄相位在每个 physics step 更新一次，接触约束在子步循环前一次性生成。容量超限只会在 solver 内部被标记，尚没有把破坏事件反馈给体素拓扑、局部窄相位或同一子步的重新求解。

## 主要差距

| 能力 | 当前实现 | 与参考目标的差距 |
| --- | --- | --- |
| 破坏后的接触处理 | 有材质冲量上限、接触失效的基础数据通路和局部约束图结构。 | 新暴露表面不能在当前子步内完整重建接触流形；失效玻璃接触可能继续作为旧墙体约束参与剩余迭代。 |
| 体素与碰撞表示 | CCC 采用 sparse `8³` brick；Avian 提供通用 collider、narrow phase、子步 solver 和约束图。 | 尚未验证大规模碎片堆积、并行求解效率，以及碰撞发布相对体素编辑的端到端延迟。 |
| 物理、网格、渲染同步 | 数据、碰撞和网格在架构上分层，dirty 更新边界已经明确。 | 缺少经端到端验证的版本号/发布协议、异步转换延迟控制和可扩展属性系统；当前资料主要描述架构，不等同于公开验证的破坏求解器。 |
| 应力与碎片动量 | 有材料能量、应力和连通性驱动的破坏逻辑。 | 尚未形成等价于论文中的点质量、距离约束和拉格朗日乘子内部断裂力计算，也没有完成碎片质量、线速度、角速度和耗能的守恒验证。 |

## Voxagon — Smash Hit 破坏求解

参考方向强调：接触失效后，solver 应在同一时间步内放弃已经不存在的实体表面，并尽快为新表面建立可用接触。

当前已有：

- 材质法向冲量上限；
- restitution 和 warm-start 阶段的容量约束；
- 受影响约束可在约束图中局部定位。

当前仍缺少：

- 由容量超限或体素拓扑编辑触发的受影响接触岛标记；
- 当前子步内的局部 narrow phase、流形和约束重新生成；
- 有次数上限、可诊断、可回退的 local re-solve；
- 明确的 contact/voxel revision，避免旧碰撞体在异步发布期间继续冒充权威几何。

## Voxagon — 新一代体素引擎

CCC 已经采用稀疏 `8³` brick 和 dirty-region 思路；Avian 已经有子步求解和约束图。剩余差距主要是测量而不是再写一份架构描述：

- 碎片数、活动接触数和约束图颜色数增长时的求解耗时；
- brick 编辑到 collider 发布、首次接触可用的延迟；
- collider 发布到 Mesh/BLAS 可见的延迟；
- 大量碎片进入 sleeping、合并或清理路径时的帧尖峰；
- 多线程窄相位与约束图更新的可重复性。

## John Lin — The Perfect Voxel Engine

已有体素数据、碰撞表示、网格和渲染之间的分层。要达到可用工程闭环，还需要：

- 所有派生表示携带同一个 source revision；
- collider、mesh、BLAS 发布采用可观测的 generation/revision 协议；
- 编辑、碰撞、网格、渲染之间的最大允许异步延迟与丢帧策略；
- 材质、密度、断裂强度、支撑强度等属性的版本化与扩展边界。

这篇文章的价值在于架构分层；不能把它当成已经公开验证的破坏求解器基准。

## Smith / Witkin / Baraff — 脆性断裂论文

当前的能量、应力和连通性逻辑可以作为游戏化近似，但还需要建立可测试的内部模型：

- 断裂前后的点质量/刚体质量和惯量变化；
- 约束力或拉格朗日乘子的时间积分；
- 断裂耗能与剩余动能的预算；
- 碎片线动量、角动量和接触冲量的守恒误差；
- 梁、窗框、支撑节点的拉伸/压缩/弯曲区别。

## 下一步最值得解决的三个问题

### P0 — 完整同一步断裂重求解

向 Avian 暴露一个受影响接触岛的局部 narrow phase、约束重新生成和 bounded re-solve 接口。容量超限或体素编辑使接触失效后，旧接触必须在剩余子步中停止施加墙体阻挡；新暴露表面应在次数上限内获得接触流形。失败时应记录诊断并安全退回到下一子步，而不是继续使用已失效接触。

验收条件：

- 一个高速物体撞击可破坏玻璃时，失效接触不会在同一子步剩余迭代中继续施加完整墙体冲量；
- local re-solve 次数有硬上限，且不会递归触发无限求解；
- 2D/3D 回归测试覆盖：接触失效、重新生成、旧 warm-start 清理和静态/动态两种对手。

### P1 — 应力传播与碎片动量

对梁、窗框和支撑节点建立载荷路径，记录断裂前后的质量、质心、惯量、线速度、角速度、接触冲量和破坏耗能。先保证守恒误差可测，再逐步增加材料模型复杂度。

验收条件：

- 无外力断裂测试的线动量和角动量误差有明确阈值；
- 碎片质量之和与被移除体素质量一致，允许的数值误差可配置；
- 断裂耗能不会凭空产生负能量或无限增能。

### P2 — 物理到视觉的一致性

分别计时 voxel edit、fragment creation、collider publish、mesh build、Mesh asset update 和 BLAS rebuild。所有阶段都携带 source revision，并在诊断中报告编辑到碰撞可用、编辑到画面可见的延迟。

验收条件：

- 已穿透玻璃的画面不会继续显示完整玻璃超过设定延迟；
- 大量碎片的 Mesh/BLAS 更新有预算和降级策略；
- 运行时日志能按 revision 对齐物理、碰撞和渲染状态。

## 结论

当前 fork 已从“普通刚体接触”迈向“可破坏接触”的 solver 基础，但距离参考技术的关键差距集中在同一步拓扑变化后的重求解、守恒可验证的断裂动力学，以及物理到视觉的版本化发布。P0 应先于大规模碎片和渲染优化完成；否则后续性能数据会混入失效接触造成的物理错误。
